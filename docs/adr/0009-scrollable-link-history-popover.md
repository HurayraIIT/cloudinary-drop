# A scrollable Link History in an AppKit popover

The Link History retains the 50 newest Uploads rather than ten, in an AppKit popover with the existing 420 pt width and a capped normal height. Only the Link History scrolls; Usage and the existing commands stay visible below it. Two-line rows put the filename above size and time, with roughly seven entries visible at once. A long Last Error increases the popover's height so the full message remains visible; if it exceeds the available screen height, the error itself scrolls without truncation. New Uploads and background refreshes preserve the visible position and selected entry while the popover is open; reopening starts at the newest entry. Copy, Open and Delete continue to close the popover, and existing keyboard behavior and the Settings submenu are retained. A plain NSMenu was considered, but its overflow scrolls the commands with the Link History and does not provide the chosen height. The popover trades AppKit's built-in menu navigation for explicit keyboard, focus and accessibility handling. It keeps the existing NSStatusItem and its Drop receiver, and uses no web view or new dependency.

Fifty entries still fit one Search API request, with the existing refresh schedule. Thumbnail work prioritizes visible entries and two following entries, with at most two requests at once and an in-memory cache bounded to the retained list. The table reuses rows rather than constructing all fifty, and existing 44 px thumbnails are kept to avoid generating new Cloudinary transformations. Resource impact must be measured on the M1 Air; the design does not establish a measured CPU or memory result.
